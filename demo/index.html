This page is a real MCP client running in your browser. It speaks raw JSON-RPC over Streamable HTTP to a Cloudflare Worker that runs the db-timetable-mcp server and holds the API credentials. No REST wrapper in between — open the protocol panel to see the messages.

    What this is

    db-timetable-mcp is an MCP server for the official Deutsche Bahn Timetables API. It exposes five tools — getStationBoard, findStations, getPlannedTimetable, getCurrentTimetable, getRecentChanges. The board above is a single getStationBoard call: the worker merges the planned timetable with the realtime changes and marks the effective values. This page is a demonstration of that server running in an edge runtime, driven by a browser client instead of an AI agent.

    Limits

    The operator's DB API quota is personal and small. The worker caches upstream calls and degrades to cached data instead of failing, so that a popular page does not burn the quota.

    Measured/configured values
    ResourceLimitWhat happens at the limit
    Cache: live data (getCurrentTimetable, getRecentChanges) 30 s fresh Upstream is called once per 30 s per station board, no matter how many visitors.
    Cache: getPlannedTimetable 1 h fresh Timetables for a given station/date/hour are static per hour.
    Cache: findStations 24 h fresh Station data effectively never changes.
    Stale cache window 6 h If the upstream quota is exhausted or the API is down, the last snapshot is served and marked stale.
    Rate limit per IP 20 / min, 200 / h HTTP 429 with Retry-After. Best effort, see note below.
    Circuit breaker 30 s open After one upstream 429, no further upstream calls are attempted for 30 s.
    DB Timetables API quota 60 requests / min (per marketplace terms) Shared by every visitor. The cache is what keeps this from being hit.
    Cloudflare Workers Free 100,000 requests / day Beyond that the worker stops serving until the daily counter resets. No automatic billing on Free.
    GitHub Pages Free 1 GB repo, 100 GB bandwidth / month, 10 builds / hour Soft limits enforced by GitHub; the site may be blocked until the next period.

    Honest note on rate limiting. Cloudflare's Free plan has no rate-limiting product, so this is a best-effort counter in the memory of a single worker isolate. Each isolate keeps its own counters and loses them on redeploy or eviction, so the effective limit is roughly “20 per minute × the number of active isolates”. It blunts accidents and abuse, it does not stop a determined attacker. The cache plus the circuit breaker are what actually protect the upstream quota. A Durable Object would be the correct fix and is deliberately out of scope for this demo.

    Privacy

    • This page sets no cookies, uses no analytics, no tracking pixels, no third-party requests. All assets are served from this origin; there are no external fonts or CDNs.
    • Your station searches are not stored anywhere. The worker answers and forgets.
    • The worker uses your IP address in memory only to count requests against the rate limit. Counters are never written to storage or logs.
    • The worker logs the upstream API path it fetched (for example /plan/8000105/260910/16) so the cache can be verified. It does not log your IP or the content of your requests.
    • Cloudflare processes requests as the hosting provider and may keep operational logs; GitHub Pages does the same for the static files. See their respective privacy statements.

    Run your own

    About ten minutes, all on free tiers.

    1. Get credentials for the Timetables API at the DB API Marketplace.
    2. git clone the repository and npm install.
    3. Deploy the worker: 
      cd worker
cp .dev.vars.example .dev.vars   # lists the exact secret names
npx wrangler secret put <id-secret>
npx wrangler secret put <key-secret>
npx wrangler deploy
      worker/.dev.vars.example and the repository README name the two variables. Wrangler prints the worker URL.
    4. Set ALLOWED_ORIGINS in worker/wrangler.toml to the exact origin that serves this page, then deploy again. CORS fails loudly otherwise.
    5. Point the page at the worker: set DEFAULT_ENDPOINT in demo/app.js, or append ?endpoint=https://your-worker.workers.dev/mcp.
    6. Serve demo/ anywhere static — GitHub Pages via the included workflow, or npx serve demo locally.

    The credentials live only as worker secrets. They are never sent to the browser, never written into this repository, and never logged.

    What breaks at the limit

    • Upstream quota exhausted (60/min). The page keeps working from cache and marks data as stale. The board shows the last snapshot with its age. Once the quota resets, fresh data returns automatically.
    • No cache and no quota. The tool call returns a stable error code (UPSTREAM_UNAVAILABLE / RATE_LIMITED) and the page shows a retry hint. No blank screen, no stack trace.
    • Too many requests from one IP (20/min). The page shows the throttled state and the seconds to wait. Reloading makes it worse.
    • 100,000 worker requests/day. The worker stops responding for the rest of the day. The static page still loads; board requests fail. Staying below this is what the client-side session cache and the 30 s refresh discipline are for.
    • Going beyond the free tier. Workers Paid starts at $5/month and removes the daily request cap. The DB API quota is the harder ceiling: the cache buys a factor of ~1,000, not an unlimited budget.
